Polish screening-call voicebot with ATS write-back

The bot calls a candidate, checks it is the right person, asks 11 screening questions, turns free Polish answers into fixed ATS values, answers candidate questions only from the FAQ, and saves every answer through a REST API — with retries when the API is down. The agency, candidates and API are fictional; the dialogue logic is real.

1 · Call request
The ATS sends a call request for a candidate. The bot dials; no answer and voicemail are saved as call results and scheduled for retry. On voicemail the bot leaves a short message without any personal data.

  
2 · Right person?
The bot says it is an AI assistant, then confirms the name. If a family member answers (“nie, tu córka, zaraz zawołam tatę”) the bot waits on hold, re-introduces itself to the new speaker and checks identity again; it never tells a third person why it is calling. “Nie ma go” gets a callback time; “pomyłka” ends the call and marks wrong_person.

  
3 · 11 questions → fixed values
Each answer goes through a field-specific normalizer: relative dates (“po świętach”, “za dwa tygodnie”), licence categories (“tir” → C+E, “2 WJO” → II WJO), German level, experience in months or years. The bot reads the value back so the candidate can hear what was saved.

  
4 · Unclear or silent
The bot asks again in a different way. After two failed tries the field stays empty and the call note says why, so a recruiter can follow up. Fillers (“yyy”, “no więc”) and self-corrections (“od poniedziałku, a nie, od wtorku”) are handled.

  
4b · What callers really say
“Proszę powtórzyć” and “nie rozumiem” repeat or explain the question without using up a try. “Chwileczkę” makes the bot wait. “Nie mam teraz czasu” asks for a callback time and keeps the answers so far. “Chcę rozmawiać z człowiekiem” hands off to a recruiter. “Proszę więcej nie dzwonić / usuńcie dane” records an opt-out (GDPR). “Już znalazłem pracę” closes the call politely.

  
5 · FAQ only from the client's sheet
When the candidate asks something (“a ile kosztuje zakwaterowanie?”), the bot answers from the FAQ table, shows which entry it used, then returns to the open question. Anything not in the FAQ is never improvised; it is logged for the recruiter.

  
6 · Write-back that survives outages
Every answer is saved right away (a dropped call keeps what was collected). If the ATS API returns 503 the bot retries with backoff, then holds the request in an outbox and sends it when the API is back. Requests are idempotent, so a retry never writes twice.

  
7 · Module C · job offer
Same integration: the bot presents one offer, answers FAQ questions, and saves interested / not_interested / no_decision. “Muszę pogadać z żoną” is a no decision, not a no.

  
On a real platform
This demo runs in the browser (Web Speech for voice). In production the same flow, value mapping and error handling are built on the voice platform's own telephony, ASR/TTS and HTTP integration blocks.
